Attached are HTML files containing betting odds. Your task is to perform OCR, parse the files, and extract all available betting lines into a single, structured JSON object.



You must adhere to the following rules for filtering events and structuring the JSON output.



**1. JSON Output Specification**



The final output MUST be a single JSON object. The entire output must be enclosed in a single json code block. Use the following nested, market-centric structure:



{

  "Sport Name": [

    {

      "eventName": "Event Name (e.g., Genesis Invitational, Super Bowl LIX)",

      "startTime": "YYYY-MM-DD HH:MM",

      "eventType": "matchup OR tournament",

      "markets": {

        "Market Name (e.g., Moneyline)": [

          {

            "name": "Name of the betting option (e.g., Team A, or Over 2.5)",

            "odds": "Odds value (e.g., -110)"

          }

        ],

        "Market Name (e.g., Spread)": [

          {

            "name": "Team A",

            "odds": "-3.5 (-115)"

          },

          {

            "name": "Team B",

            "odds": "+3.5 (-115)"

          }

        ]

      }

    }

  ]

}





**2. Data Mapping and Formatting**



For each event that passes the filtering criteria, populate the JSON structure as follows:



  * **A. Group by Sport:** Use the name of the sport as the top-level key in the JSON object. All events for that sport should be objects within the corresponding array.



  * **B. Structure by Market:** All betting lines for an event must be organized by their market type (e.g., "Moneyline", "Spread", "Total Rounds", "Winner") inside the `markets` object.



      * Each market is a key in the `markets` object.

      * The value for each market key is an **array of objects**, where each object represents a distinct betting choice.

      * Each choice object must contain a `name` (the participant or option, e.g., "Team A" or "Over 2.5") and its `odds`.



  * **C. Determine `eventType` and Populate Markets:**



      * **For Head-to-Head Matchups (e.g., NFL, NBA, Tennis):**



          * Set the `eventType` field to `"matchup"`.

          * Populate the `markets` object with all available betting lines.

          * For participant-based markets ("Moneyline", "Spread"), the `name` will be the participant's name.

          * For event-based markets ("Total Rounds"), the `name` will be the option (e.g., "Over 48.5", "Under 48.5").



      * **For Tournament & Futures Events (e.g., Golf Tournament Winner, NASCAR Race Winner, League Champion):**



          * Set the `eventType` field to `"tournament"`.

          * Populate the `markets` object with the primary market (e.g., "Winner", "Outright").

          * The market's array must contain an object for **every single participant** listed for that event. Do not summarize, truncate, or omit any participants.

          * Each object must contain the participant's `name` and their `odds`.



**3. HTML Parsing and Data Association Logic**



To prevent common data entry errors, you must follow these parsing rules based on the principle of **Positional Proximity**: data elements that are close to each other in the HTML code are related.



  * **A. For "Fight Lines" / Main Event Pages:**



      * Matchups are presented in consecutive horizontal rows or blocks (e.g., `div.cms-market-selector-static__content`), one for each participant.

      * The first block contains Participant 1's name and their associated odds (their Moneyline, their side of the Spread, and the "Over" for the Total).

      * The second block contains Participant 2's name and their odds (their Moneyline, their side of the Spread, and the "Under" for the Total).

      * **Crucially, you must extract the odds from the *same container element* as the participant's name to ensure they are not mixed up.** For Totals, you must identify the "O" or "U" text *within the same button element* as the odds value to avoid swapping them.



  * **B. For "Prop Bet" / Market-Specific Pages (e.g., "Method of Victory," "Round of Finish"):**



      * These pages typically group all options for a single market under one expandable event header.

      * The betting options are listed as a sequence of label-button pairs.

      * The text describing a specific bet (e.g., "Asu Almabayev To Win By KO/TKO/DQ" or "Fight to Go the Distance - Yes") is located in an element that is an **immediate sibling or in very close proximity to the button element containing its odds.**

      * **You must parse these as label-and-button pairs.** Never associate a descriptive label with an odds button that is several elements away in the HTML structure.
